# App 创作者流程补丁

> **已停用，仅保留为历史方案。** 用户确认 App 由其他团队维护，不部署此目录的 PHP 或 SQL。创作者平台已调整为现有 App 接口兼容模式；下文部署步骤为历史记录，不再是当前执行计划。任何后续 App 修改均需用户与 App 团队另行确认。

本目录是针对用户提供的 401 App PHP 源码制作的补丁，**尚未发布到正式 App**。创作者网站和 CMS 的修改在主项目 `src`、`backend` 中。

## 包含的改动

- `CreatorWithdrawalDecision`：只允许待处理申请进入已付款或驳回；行锁、事务、一次退款；已付款必须填写银行回单/流水编号；禁止通过批量编辑或删除绕过审核。此服务不会自动打款。
- `User.userWithdrawal`：可接收 `creator_request_id`，同一账号同一申请只扣一次积分；`getCreatorWithdrawalRequest` 按登录账号和唯一申请编号只读核对。CMS 仅在账号、编号、金额全部匹配时解除结果不明状态。
- 数据库触发器：记录剧目、剧集、创作者视频的新增、修改、下架和删除。保留变更前后值；媒体 URL 只记录摘要。管理员和 App 用户身份从服务端认证取得；直接 SQL 写入只能标记数据库身份，不能推测实际操作者。
- `creator/audit/index`：只读审计查询，使用 App 原有管理员权限。日志表禁止 UPDATE/DELETE；数据库超级管理员仍能更改数据库结构，这不是防数据库管理员篡改的外部存证。
- App 流水扩展作品归属字段，`LogService.recordScoreLog` 可在最后一个可选参数接收 `{drama_id, episode_id, basis}`，在同一笔分润入账中保存。只允许分润收入并验证剧集与剧目关系。

## 部署顺序

1. 对照 `manifest.json` 的原始文件 SHA256 核实正式源码版本；不同则逐处合并差异，不能直接覆盖较新的 App 改动。
2. 暂停提现审核和相关内容编辑，备份 App 数据库及待替换文件。
3. 由具备建表、修改表、触发器权限的部署账号在 **App 数据库**依次执行 `001_operations_and_settlement.sql`、`002_earning_references.sql`。这是一次性迁移，表前缀按当前源码为 `fa_`；重复执行前必须核对迁移状态。
4. 部署 `application/` 中的文件并清理 PHP OPcache。不要复制本目录的测试夹具到公网。
5. 给需要查询全局日志的 App 管理角色分配 `creator/audit/index`。提现使用原 `recharge/withdrawal/index`、`recharge/withdrawal/edit` 权限，不向企业普通成员开放。
6. 再发布主项目 CMS 和 Next 网站。网站会检查 App 提现接口是否包含新字段，旧版服务不会开放处理按钮。
7. 使用约定的 App 测试账号做一次完整接口验收，再开放相关入口。这里没有执行真实提现或打款。

## 已验证与边界

- `tests/legacy-rejection.php` 在原控制器上复现一次申请被重复退积分。
- `tests/settlement-integration.php` 使用独立 `app_creator_completion_test` 数据库，运行补丁中的 PHP 提现控制器、退款决策和积分记账业务代码；用 PDO 适配器替代 ThinkPHP ORM/认证环境，未声称验证了正式 App 的路由、角色、银行网关或生产部署。
- 覆盖：重复提交仅一次扣款、一次申请记录；人工付款凭证必填；重复驳回/付款后驳回被拒绝；退款记账失败余额回滚；审计新增/下架/删除和禁止篡改；作品归属字段随实际分润流水保存。
- PHP 便携测试运行时位于主项目 `.data/php-runtime`，不部署。命令：
  `php -d extension=pdo_mysql -d extension=mbstring tests/settlement-integration.php`
  运行时需配置自己的 extension_dir。本地测试库固定在 127.0.0.1:3309，不应改成生产地址。

## 不能凭空补齐的历史数据

- 审计部署前 App 已经删除的记录，无法恢复删除者和原因；现有审计不能伪造过去的日志。
- App 公共详情未返回剧集，可能是删除、下架或不公开，创作者界面显示“未返回”并由后台审计核对，不把它直接认定为物理删除。
- 原账号汇总分润没有作品来源。现有批量分润调用不传作品参数，继续归入“尚未归属项目”。必须由 App 实际按作品结算的入账流程提供对应编号和依据，才能出现项目收益；不能按播放量或项目数量平均分配。
- 旧提现没有唯一申请编号时不能自动匹配并解除不明状态；需要 App 财务人员用原申请和流水核实，不能只按相同金额猜测。
- 恢复发布入口可重新上架仍存在且媒体一致的 App 记录。若整部剧目和多集关联已被删除，须先由 App 后台恢复记录或逐项核实重新关联；本补丁不自动重建未知的已删除剧目/云媒体。
